## 2. Сильные стороны (подтверждено кодом и тестами)

- Server-authoritative mock: дедлайны, идемпотентная финализация, снимки вопросов, anti-repetition, восстановление попытки.
- Честная оценка: `practice_feedback` / rule-based помечается как тренировочная, gibberish/stopwords отсекаются, провал провайдера не превращается в ноль.
- Персонализация: обязательная цель, план на день в рамках доступного времени с причиной, readiness только от ≥2 попыток.
- Coach: сравнение попыток, evidence → fix, Error Notebook, удаление аудио по владельцу.
- Университеты: реестр 4 087, карта 2 185 с проверенными координатами, provenance у требований, «неизвестно» вместо выдуманного балла.
- Retention: серверный XP-ledger с идемпотентностью, недельные лиги из ledger, боты не влияют на рейтинг.
- Платформа 100% бесплатная: биллинг/пейволлы исключены осознанно.

## 3. Найденные проблемы

### P0 — ломает продукт или доверие

1. **Таймер Speaking перезапускался на каждом обновлении рекордера** (`SpeakingSample.tsx`, коммит `10546da` добавил `startRecording` в deps эффекта). Таймер не доходил до порога, кнопка «Далее» оставалась disabled, этап нельзя было завершить вручную. Причина зависаний локального E2E и 100% CPU у `next dev`. **Исправлено** (`1998257`).
2. **Speaking не оценивался на production**: клиент отправлял распознанный текст, но `ALLOW_CLIENT_TRANSCRIPT` по умолчанию `false` → каждая попытка получала `INSUFFICIENT` и 0. **Исправлено** (`1e38c79`), результат помечается как тренировочный.
3. **Мало промптов продуктивных навыков**: 2 промпта на каждый speaking-тип, 5 writing sample → одни и те же задания в каждом mock. **Исправлено**: +104 задания (`f6d502f`), итого 375 вопросов в БД.
4. **Калибровка не подтверждена production-данными**: 54-item датасет помечен `fixture: true` («synthetic benchmark fixture with dual simulated raters»), `--production` даёт `fixture_only`. Нельзя заявлять QWK ≥ 0.70 как доказательство; нужны ≥50 реальных ответов и два независимых эксперта.
5. **AI/STT не настроены**: работает rule-based практика; neural evaluation и серверный STT требуют провайдера.

## 4. План

### Неделя 1–2: AI как основной путь оценки

1. Подключить OpenAI-compatible провайдера: `AI_BASE_URL`, `AI_API_KEY`, `AI_MODEL`; STT — `/audio/transcriptions` (Whisper/Groq), `AI_STT_ENABLED=true`.
2. Preflight провайдера (чат + STT + JSON-схема), таймауты, retry, потолок стоимости, кэш по хэшу ответа.
3. Writing → rubric JSON в промпте; Speaking → STT → rubric. LLM не меняет числовой score (рубрика считает сервер).
4. `REQUIRE_NEURAL_EVALUATION=true` в staging; при недоступном провайдере — `pending/failed`, не ноль.
5. Собрать 50+ реальных ответов, разметить двумя экспертами, прогнать `calibration_validate.py`; только после QWK ≥ 0.70 включать production-заявление.
6. С появлением STT: `ALLOW_CLIENT_TRANSCRIPT=false` в экзаменационном режиме, `true` — в тренировке.

### Неделя 3–4: контент и аналитика

7. Расширить интерактивные типы до 20+ и добавить A2.
8. Дашборд администратора на learning events: DAU/WAU, воронка (регистрация → диагностика → mock → сертификат), retention D1/D7, распределение баллов, возраст очереди.
9. Единая модель университетов: реестр → карта → matching, с явным «на карте только проверенные координаты».
10. Напоминания: in-app + Resend (когда решён вопрос с Beget).

### Неделя 5–6: инженерия и удержание

11. Разбить крупные сервисы/репозитории, вынести доменные пакеты.
12. Frontend unit-тесты для чистой логики (IRT, scoring, plan builder) — сейчас только e2e.
13. Очистка SW-кэша при logout, паритет локализации, региональная загрузка карты.
14. Streak freeze и недельные цели.
