# DET Academy — roadmap after full-team review

Date: 2026-11-01  
Reviewed by: architect, senior full-stack engineer, product designer, cybersecurity,
SRE/DevOps, QA, AI/data, SEO/content, performance/a11y.

Production snapshot: `becbc73`, `/ready` 200. The product is technically deep, but
release governance, data integrity and trust claims lag behind the code.

## Executive summary

The platform’s core is sound: server-authoritative mock attempts, item snapshots,
idempotent completion, consent-gated export, versioned theory catalogue, tagged
deploys with rollback images. The next risk is not a missing feature. It is the
gap between what the product claims and what the system can prove.

Five things need action before any new feature:

1. **Directus leaks the answer key.** Public read on `questions` exposes
   `correct_answers`; the CMS also uses a broad DB role.
2. **Disk and backups are not safe.** The host was at ~91% in the latest SRE
   snapshot; the cleanup job exits early; nightly DB/media backups are not
   empirically verified.
3. **CI is not a release gate.** The deploy workflow can ship a SHA whose CI is
   red; most Postgres tests are skipped.
4. **Scoring/calibration can produce wrong evidence.** Writing enqueue errors
   become zero scores; certificates are possible at ~30% answer coverage; the
   calibration exporter joins on an unpopulated `response_id`.
5. **Mobile test UX breaks with real tasks.** Populated `READ_SELECT` overflows
   at 390 px; `/test/session` is absent from the axe gate.

## Status after the first implementation pass (2026-11-01)

Production was `becbc73` when the review started. It is now `21ef06e` /
`v2026.11.01-3` (Deploy #7, green CI gate, `/ready` 200). `master` is `3a99dd5`
with the cleanup and documentation follow-ups.

Closed or materially improved:

- **P0-1 Directus answer key:** public `questions` permissions removed; the Next
  proxy no longer allows `questions`; both direct and proxied requests return 403.
- **P0-2 disk and cleanup:** `cleanup_host.sh` no longer exits under `pipefail`,
  logs a completed run, and alerts at 80/85/90%. A 28.4 GB build cache and
  2.5 GB of dangling images were reclaimed, taking the host from 85% to 43%.
- **P0-3 backup and restore:** DB and media share one `BACKUP_STAMP`; the nightly
  workflow restores into a disposable Postgres and checks every media row. A
  real drill restored 90 users, 110 sessions, 1193 responses and 44 media files.
- **P0-4 CI gate:** deploy now waits for a green CI run for the exact SHA and has
  a tag guard; e2e runs against a production build with bundled Chromium; the
  Postgres suite is enabled; Playwright reports/traces are uploaded.
- **P0-5 scoring integrity:** writing enqueue failures roll back instead of
  recording zero; overall score and certificate require 90% answer coverage; the
  stale-job reaper marks the linked evaluation failed.
- **P0-6 calibration export:** current task names, `response_id` backfill and
  unique index (migration 036), consent `granted_at` bound, readable text
  extraction and PII redaction.
- **P0-7 mobile reflow:** long `READ_SELECT` words, `WRITE_PHOTO` header,
  `LISTEN_TYPE` play label and the `/practice` CTA fit 320 px; populated mobile
  tests were added.
- **Additional security:** certificate public IDs are random 128-bit values;
  admin self-demotion/self-deletion and last-admin removal are blocked; refresh
  uses a cross-tab lock and a short reuse grace instead of logging out both tabs.

Still blocked or open:

- **P0-8 credentials:** Sentry, Telegram and the Yandex budget alert need owner
  credentials/console access.
- **P1 auth:** closed. New sessions keep the access token out of
  `localStorage`, use HttpOnly cookies plus a double-submit CSRF token, require
  a server-issued OAuth link transaction, and separate `superadmin` from
  `admin`. Password reset is single-use, 30-minute, hash-only, generic for
  unknown emails and revokes all sessions. App routes now use a per-request CSP
  script nonce; `style-src` still needs `'unsafe-inline'` for Next/Tailwind.
- **P1 content/trust:** retired task types in theory, full server-rendered EN,
  verified institution thresholds, and unsourced claims.
- **P1 scale:** dashboard waterfall, zero-downtime deploy, managed Postgres and
  offsite media storage.

## Phase 1 — security, correctness, trust (1–2 weeks)

### Security
- Migrate access token from `localStorage` to HttpOnly cookie + CSRF token;
  remove `unsafe-inline` from CSP; move Directus to a separate origin.
- OAuth link flow: require authenticated `/oauth/start`, verify state cookie in
  link consume, stop static client-built state.
- Refresh: cross-tab coordination plus short reuse grace (`replaced_by`) so two
  tabs do not revoke the family.
- Admin: `superadmin` separation, self-demote/last-admin protection, audit all
  admin/CMS mutations and PII reads; password change revokes access tokens.
- Certificate IDs: random 128-bit public ID, rate limit, return minimal fields.
- Rate limits: per-account lockout, persistent TTS quotas, magic-byte upload
  validation, pin image digests/Action SHAs, `.env` 0600.

### Data and evaluation
- Make evaluation + job + response one transactional/outbox flow.
- Lease token + heartbeat for long STT/LLM jobs; reaper updates evaluations.
- Score unanswered/INSUFFICIENT items explicitly instead of dropping them.
- Server-side audio duration (ffprobe), audio-backed practice speaking.
- SRS/XP/typing daily caps and server plausibility checks.
- Practice must display the server verdict; local verdict only when not saved.

### Test engine and UX
- Mandatory mic/camera/network preflight before a mock; pause timer on device
  failure; retry/switch/skip with explicit scoring impact.
- Autosave writing drafts every 5s, restore after refresh, warn on unload.
- Missing-item recovery: retry/skip/support, never a dead end with a running timer.
- Offline banner with unsynced-answer count; stage does not auto-advance until
  server acknowledgement.
- Result page: primary “Continue plan”, report page, clickable history, PDF/share;
  replace “certificate” with “training report” until calibration passes.

### SEO/content trust
- Rewrite curriculum: remove retired Listen & Select / Read Aloud / Listen Then
  Speak as exam tasks; add Interactive Speaking; correct keyboard/proctoring
  claims; add author, reviewer, last-reviewed date, official links.
- Institution pages: “DET score reference / registry listing”, not “acceptance”;
  put “unverified platform estimate” next to every number; add `/methodology`.
- Homepage canonical + Organization/WebSite JSON-LD; unique metadata for
  `/practice*` and `/verify`; remove auth-only pages from sitemap.

## Phase 2 — architecture, performance, scale (2–6 weeks)

### Architecture
- Stop startup migrations; one locked migrate job, no re-running `init.sql`.
- Authenticate with request context + short-TTL role/version cache.
- Split Postgres repositories by aggregate; run handler tests against Postgres.
- Split `CATService` into IRT/selection/grading/session/review packages.
- Dedicated evaluation worker with bounded concurrency, per-job timeout, lease
  heartbeat, ffmpeg pool, queue-age SLO.
- Server owns test results, streak, ELO, XP; localStorage becomes a versioned
  read-through cache. Keep outbox only for unsynced writes.

### Performance
- Fix 15s socket read timeout vs 1–2 MB audio uploads: 120s per-route upload
  deadline, slow-network regression test.
- `next/dynamic` for 13 test stages; prefetch next stage; dynamic confetti.
- Theory routes RSC/ISR with `generateStaticParams`; no client refetch.
- Dashboard aggregate endpoint or `Promise.allSettled` + fixed-height skeletons.
- `priority` for LCP task images; local AVIF/WebP; batch `AssignQuestions`;
  `Cache-Control` for public catalogues; web-vitals RUM.
- Route-level gzip budgets in CI, not only per-chunk size.

### Operations
- Zero-downtime deploy: build/push images, health-check frontend too, switch
  upstream, keep old container hot; retain 3 releases by digest.
- Zero-trust CI: deploy on green SHA only; migration dry-run on a production
  snapshot; post-deploy login + full-mock smoke.
- Container resource limits, log rotation, SSH hardening, close unrelated DB
  ports, Directus admin behind VPN/IP allowlist, PITR to object storage.
- Monthly restore drill and quarterly rollback drill.

### Internationalization
Decide one strategy:
- **Preferred:** server-rendered `/[locale]/...` routes with translated metadata
  and body, self-canonical, sitemap alternates.
- **Interim:** noindex `/en/*`, remove hreflang until the body is translated.

Do not keep hreflang pointing to Russian-canonical pages.

## Phase 3 — authority and durability (1 quarter)

- Verify top 100 institution thresholds against institution-specific sources;
  index `/det-score` only for verified rows.
- Tier institution pages: index only pages with verified facts + website +
  programs; noindex/consolidate the rest; paginate country hubs.
- Dictionary: keep pages with real editorial value; add level/source hubs and
  review stamps.
- Calibration service: consent-at-capture, append-only consent events, rater
  attestation, export hash, QWK gate; 50+ real items and two accredited raters.
- AI economics: per-model pricing table, STT/TTS chunk accounting, per-user
  budget guard, invoice reconciliation, kill switch.
- Scale: managed Postgres/read replica, object storage + CDN, staging, load tests,
  DR game day, status page.

## Sequencing

1. **Day 0:** Directus leak, disk, backup/restore, CI gate.
2. **Week 1:** scoring/calibration integrity, mobile reflow/axe, Sentry/Telegram.
3. **Weeks 2–3:** auth migration, OAuth link, refresh grace, admin RBAC/audit.
4. **Weeks 3–4:** evaluation transaction/lease, score coverage, practice verdict,
   test preflight/autosave, trust copy/curriculum.
5. **Weeks 4–6:** deploy zero-downtime, frontend health, Postgres CI, theory RSC,
   stage code-splitting, dashboard aggregate.
6. **Quarter:** SEO tiering, full i18n, calibration, PITR/object storage, load/DR.

## Metrics to add

- **Reliability:** `/ready` and frontend 200 rate; 5xx by route; eval queue age;
  permanently_failed rate; backup age; restore last-success; disk/inodes.
- **Learning:** diagnostic completion, mock completion, 13-stage completion,
  result → next session, report downloads, consent opt-in.
- **Scoring:** answer coverage at completion; unmeasured skills; calibration QWK;
  human–model disagreement.
- **Cost:** AI RUB/day, TTS requests/day, cost per evaluation, forecast.
- **Web:** LCP/INP/CLS p75, JS gzip per route, mobile reflow, axe critical count.

## What not to do now

- Do not add Arena/leagues/duels or new AI features before P0/P1.
- Do not rewrite the server-authoritative session core; it is a strength.
- Do not build a second CMS or a parallel alert transport; fix Directus/Sentry.
- Do not claim official DET scores or calibration until the gate passes.
- Do not expand programmatic SEO before institution/curriculum trust is fixed.
